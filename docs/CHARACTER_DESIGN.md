# 角色造型、动作与细节打磨方案

更新：2026-10-18。对应 T10 / F12。用户确认：**直接完成第一轮重绘，并留下后续方案**。本文件将现有证据、已实现内容和后续工作分开，当前实现入口为 `src/presentation/CharacterPainter.ts`、`CharacterMotion.ts` 和 `CharacterArt.ts`。

## 1. 当前问题与设计判断

检查了角色绘制、外观编辑器、实战图集、武器层及五人对照图。上一版存在以下具体问题：

| 发现 | 对体验的影响 | 本轮处理 |
| --- | --- | --- |
| `style` 只参与图集 key，脸部几乎统一 | 去掉帽子后角色缺少个性，混搭后身份更不清楚 | 脸型、发型、眉眼、胡茬 / 疤痕 / 护目镜按 style 决定，帽子和服装继续独立 |
| 腿主要是矩形平移，空中只有一张姿态 | 看起来像滑行，跳起和下落难区分 | 通过髋 / 膝 / 踝绘制腿，分开上升、下落、二段跳收腿与落地姿态 |
| 开火强制覆盖跑步 / 跳跃帧 | 连射时双腿反复回到站立，看起来动作卡住 | 身体保留运动帧，武器围绕握持点独立后坐 |
| 材质主要靠整块颜色与少量条纹 | 布、皮革、金属和玻璃缺少区别 | 统一左上照明；用切面、亮边、缝线、折痕和低透明反光分别表现 |
| 只有十帧横排图集 | 增加动作后容易超过常见纹理边长 | 改为 22 个有效帧、8 列网格，单图 1920 × 864 |

推荐保持原创的 **2D 卡通、略带三分之四侧面的角色**。目前的高低平台和远距离射击更依赖轮廓、朝向和动作可读性；继续使用 TS + Canvas 生成图集即可完成这一轮，不必先引入 3D 模型、骨骼插件或素材服务器。

## 2. 每位角色的第一轮设计

| 角色 | 远处要看清的轮廓 | 近处可读的细节 | 后续可以继续打磨 |
| --- | --- | --- | --- |
| 荒野牛仔 | 上翘宽檐帽、分叉长衣、斜向领巾 | 胡茬与短胡须、六角黄铜徽章、皮带扣、枪套、帽扣、长靴饰钉与缝线 | 帽檐轻摆、独立拔枪 / 收枪、皮衣与领巾的延迟摆动 |
| 东方浪客 | 斗笠、交领、宽裤脚和斜背刀鞘 | 发髻、收敛眉眼、面部疤痕、领口包边、束带结、刀柄缠绕、布料折痕 | 袖摆与裤脚惯性、更完整的转身 / 持枪姿态；刀鞘保持装饰，不添加假近战入口 |
| 都市特工 | 贴身背心、不对称装备与低轮廓贝雷帽 | 护目镜反光、耳机麦克风、胸前铭牌、弹袋、腰包、护膝与帽徽 | 双手步枪握持、快速换匣动作、轻微观察 / 呼吸动作 |
| 星际游侠 | 圆形面罩、厚肩、背部生命支持包 | 多层头盔边框、面罩弧形反射、胸前读数、状态灯、软管、接头、手套和厚底靴 | 面罩与脸部独立层、头部轻微跟随、背包和软管二级动作；不添加没有玩法支持的喷气推进 |
| 古城守卫 | 宽肩甲、棱面头盔、羽饰与披风 | 胸甲切面、铆钉、护膝、护手、面甲通气缝和披风包边 | 分段肘甲 / 护胫、披风惯性、胜利立姿；头盔下的脸仍按 style 保留 |

所有风格共用颈部、肩部、脚底与握持位置。头饰 / 服装可以自由混搭；肤色和衣服配色继续使用已有存档字段。金属、皮革和玻璃保留各自的中性色，不把整套装备直接涂成同一种衣服颜色。

## 3. 细节应该如何分配

1. **先看轮廓**：在约 1 倍实战大小下看黑色剪影，确认帽形、肩宽、衣摆和背部附件可区分。不能用增加几十条细线代替轮廓设计。
2. **再看动作**：枪口朝向、迈步方向、空中姿态优先于表面花纹；连续射击不能锁住脚步。
3. **再看大色块与材质**：布料用折面，皮革用厚边和缝线，板甲用硬亮边，玻璃用透明的弧形反光。不要把所有边都描成相同亮度。
4. **最后补近景细节**：徽章、铆钉、刀柄、耳麦、胸屏等用于编辑器大图。回到实战尺寸检查；缩小后成噪点的装饰应简化。
5. **保持身份识别**：玩家编号 / 名称 / 保护轮廓继续使用身份色；衣服相同或皮肤相同也必须能区分玩家。

外观精修不能改变 `36 × 52` 碰撞体、脚底位置、移动 / 跳跃参数、武器威力或命中规则。帽檐、羽饰等可超出命中盒，后续应做带碰撞盒的叠图检查，避免装饰越来越大后误导玩家。

## 4. 本轮动作与技术实现

| 状态 | 帧 | 当前呈现 |
| --- | --- | --- |
| 待机 | 0—3 | 轻微呼吸，脚底与握持点保持稳定 |
| 跑动 | 4—11 | 八帧步态，膝踝弯曲、靴子抬起、衣摆变化；连射不覆盖 |
| 上升 / 下落 / 二段跳 | 12 / 13 / 14 | 起跳收腿、下落伸腿、二段跳再次收起 |
| 落地 | 15 | 短暂膝部缓冲；不移动逻辑脚底 |
| 静止换弹 | 16—19 | 另一只手向枪下方伸出；武器根据真实换弹进度倾斜 |
| 受击 | 20—21 | 收眼与暖色受击覆盖；每个图集格独立裁剪 |

`CharacterMotion` 根据已有 `ActorState` 选择身体姿态；不引入新的核心状态字段。移动和空中状态优先于换弹身体帧，避免移动换弹变成站立滑行；枪械倾斜仍按真实换弹计时显示。当前并非每把枪专属的完整换弹动画。

`WeaponLayer` 采用与画手共用的 `(16, -24)` 握持点，左右镜像、后坐角度与复活透明度保持一致。后坐不再改变身体帧。换枪保留旧射击冷却时，不能把旧冷却解释成新枪的超大旋转。

`CharacterArt` 负责缓存 key 和 22 帧图集；`CharacterPainter` 负责造型；外观编辑器沿用同一个绘制入口。图集 key 增加版本标识，防止复用旧帧布局。`ArenaRenderer` 暂停 / 倒计时冻结视觉时钟，复活清理落地和受击记录。

缓存从最多 12 组调整为稳定最多 8 组，清理时保留正在使用的纹理。单张 RGBA 图集约 6.33 MiB，八组原始像素约 50.63 MiB；这是尺寸推算，**不是实测总内存**，不包含 Canvas / GPU 副本和其他纹理。后续要测移动设备时再考虑裁紧画框、拆分上半身 / 下半身或降低采样倍数。

| C06 专属表情和胜利动作 | 后续 | 表情 / 姿态模块、结算呈现 | 五人个性不同；结果动作不影响实际对局状态 |
| C07 可读性与资源验收 | 持续 | `scripts/character-visuals.mjs`、质量模块 | 四地图不同背景、同色多人、八枪、连续换装 / 重赛、资源清理与参考机性能 |

同一 `CharacterPainter.ts` 不应交给五个 AI 同时重写。若并行制作五人，先把画笔接口和公共关节固定，再按角色拆独立画师文件，由一名集成者维护公共躯干、脸部插槽和图集。不要各自修改 `ActorState` 或存档来保存视觉时间。

C03、C04、C05 可分配给不同 AI，但共享握持点 / 身体旋转 / 生命周期改动要先由集成者确定。先把一位样板角色及左右握持做对，再扩展五人；每批都保留对照图，避免直到最后才发现缩小后不可读。

## 6. 验证与复现

- `pnpm exec vitest run tests/character-motion.test.ts`：真实移动中连续开火保留跑步、合法二段跳与下落、真实换弹完成后回到正常握持、左右镜像与状态只读、姿态索引合法。
- 启动 Vite 后运行 `node scripts/character-visuals.mjs`：检查五人共 110 个有效帧、150 种风格 / 帽子 / 服装组合、同配色装备下五张不同脸、图集边缘无裁切。输出 `artifacts/characters-lineup.png` 和 `artifacts/characters-poses.png`。
- `pnpm test:visual` / `pnpm test:browser`：实际编辑器、混搭、保存、实战、重赛、暂停修改下局生效、紧凑视口和核心浏览器流程。
- 最终验收结果见 [本轮交接](./updates/2026-10-18-character-polish.md)。自动化通过不能替代用户对画风和手感的评价。

## 7. 调研来源与适用边界

- [Phaser · Animations](https://docs.phaser.io/phaser/concepts/animations)：帧序列、Sprite Sheet / Atlas 与重用帧。支持继续采用图集完成当前 2D 动作，不要求改引擎。
- [Phaser · Textures](https://docs.phaser.io/phaser/concepts/textures)：纹理由 Texture Manager 共享，Frame 表示纹理中的矩形；支持网格化图集与显式资源清理。
- [Phaser · Sprite](https://docs.phaser.io/phaser/concepts/gameobjects/sprite)：Sprite 带动画组件，静态对象可用 Image；当前身体用 Sprite、独立武器用 Image 的划分合适。

以上为技术资料。五人的造型、细节与动作建议来自本项目代码及原图对照，不是从其他游戏复制素材，也不宣称已有用户研究证明某一种画风最好。
