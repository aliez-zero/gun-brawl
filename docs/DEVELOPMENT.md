## 2. 完成状态口径

- **已实现**：现有入口或代码路径能够执行对应行为；范围按本页说明。
- **部分实现**：已经有可用子集、基础类型或规则，但仍缺 PRD 要求。
- **未实现**：没有可运行功能。设计稿、类型扩展想法和任务卡不算完成。
- **待验证**：没有足够测试或实机证据，不从“类型允许”推导“已经支持”。

不使用整体百分比：核心原型和完整产品的工作量不同，完成一个模式入口不等于完成同名 PRD 模块。

## 4. 已落地的工程与规则

### 4.1 架构

| 层 | 责任 | 扩展时保持 |
| --- | --- | --- |
| `src/app` | 装配引擎 / UI / 存档、页面流转 | 统一入口和保存时机 |
| `src/scenes` | Phaser 生命周期、固定步运行和渲染衔接 | 不在场景内另算扣命 / 胜负 |
| `src/game/core` | 公共类型、状态、运行器、时钟、几何和生成 | 可在无浏览器环境运行 |
| `src/game/systems` | 移动、战斗、生命、胜负 | 由单一逻辑时间驱动，批量出界后判胜 |
| `src/game/ai` | 从公开状态生成角色指令 | 不直接改位置 / 生命 / 跳跃数 |
| `src/content` | 地图、武器、外观、模式和默认键位配置 | 不启动场景，不写运行中状态 |
| `src/presentation` | 键盘、程序绘制、Web Audio | 消费状态与事件，清理资源 |
| `src/ui` | DOM 菜单、HUD、对话框 | 通过回调请求操作 |
| `src/storage` | 存档端口、校验、降级和统计 | 不持久化未完成对局 |

当前没有后端、数据库、服务器权威同步或联网房间。`src/game` 不依赖 Phaser；不要引入 Arcade Physics 覆盖已有运动学。

### 4.2 当前默认参数

| 项目 | 当前值 / 约定 |
| --- | --- |
| 逻辑画面 / 步长 | 1280 × 720，1/60 秒，单次画面最多追赶 5 步 |
| 角色坐标 / 碰撞体 | 身体底部中心，36 × 52 |
| 主动跑速 / 重力 | 300 像素/秒，1800 像素/秒² |
| 地面 / 空中跳 | 720 / 620 向上速度，最多两次，落地恢复 |
| 宽限 / 输入缓存 / 穿台 | 0.1 / 0.1 / 0.2 秒 |
| 击退 | 每 0.3 秒减半；外力向量上限 900，不与主动跑速混为同一上限 |
| 手枪 | 每 0.28 秒一发；击退 480，后坐力 12，弹速 1200，射程 750 |
| 正式局 | 3 命、180 秒、3 秒开局倒计时 |
| 复活 / 保护 / 归因 | 正式复活 1 秒、保护 1.5 秒、有效敌方击退归因窗口 5 秒 |
| 练习 | 不减生命、0.5 秒回场、不计正式统计、不结算 |
| 出界边界 | 左 -96、右 1376、上 -240、下 860；碰撞体完整越过才扣命 |
| 加时 | 最高生命并列者重置一命，30 秒；再超时平局 |

当前武器命中只施加推力，没有血量或累计伤害百分比。不要为解决“打不死”另外添加血条机制。

### 4.3 输入基线

| 动作 | 玩家 1 | 玩家 2 |
| --- | --- | --- |
| 左右 | A / D | ← / → |
| 跳 / 二段跳 | W / 空格 | ↑ |
| 穿台 | S | ↓ |
| 连射 | J | Enter / 小键盘 0 / 小键盘 Enter |
| 暂停 | Esc | Esc |

`src/content/controls.ts` 同时供键盘与 UI 提示使用。按键用 `KeyboardEvent.code`；跳跃 / 穿台读按下边沿，射击读持续状态。W 与空格在同一采样内只产生一次跳跃；失焦后清空输入并忽略迟到的自动重复。

### 4.4 近期已完成修正

| 反馈 | 原因 | 已采取的改动 | 验证范围 |
| --- | --- | --- | --- |
| 初始枪打很久推不下去 | 120 推力及其衰减不足以压过全速向内跑动 | 击退 120 → 480，间隔 0.35 → 0.28 秒，玩家 / AI 同规则 | 左右边缘向内跑：约 4 次命中击出；孤立单发可回台；三组 AI 种子能被正常追击射击击出 |
| 默认键位不顺手 | 旧版方向键 + Z、WASD + T | 改为上表，键位配置与提示共用，加入跳跃 / 开火别名 | 双人独立、别名释放、同时跳跃键、重复事件 / 失焦、浏览器主流程 |

这是限定场景的回归结果，不能推出所有距离、地形和 AI 难度都“四枪必出界”。

## 5. 当前接口事实

以下均是现有接口；拟新增的数据结构在并行计划中单独说明。

| 接口 | 当前内容 | 重要限制 |
| --- | --- | --- |
| `ActorInput` | `moveX`、`jumpPressed`、`dropPressed`、`shootHeld`、`bombPressed` | `bombPressed` 是 T02 预留的按下边沿，键盘 / AI 目前固定 false；没有切枪或改键配置字段 |
| `MatchConfig` | `mode`、`map`、`actors`、`startingWeapon`、`stocks`、`duration`、`countdown`、`seed`、可选 `matchId` | 无武器池、战役 ID、自定义配置 ID；`startingWeapon` 是复活 / 加时复位目标 |
| `GameMode` | `duel-ai`、`local-duel`、`training` | 增加模式要联动标签、存档校验与统计 |
| `ActorState` | 位置 / 速度 / 外力、朝向、平台与跳跃计时、生命 / 保护 / 复活、冷却、`weapon` 实例、命中归因、统计 | 无炸弹数、已拾取武器历史；当前武器只保存一个实例 |
| `WeaponDefinition` | ID、名称、间隔、弹速、射程、击退、后坐力、`maxAmmo`（null 无限） | 只有 `BASIC_PISTOL`；T01 补六枪、有限弹和耗尽回退 |
| `WeaponInstance` | `definition`、`ammoRemaining`（null 无限） | 每角色一个实例；冷却仍在 `ActorState.fireCooldown`，切枪不清零 |
| `Projectile` | ID、拥有者、`weaponId`、前后位置、左右方向、`velocity`、`impulse`、剩余射程 | 发射时冻结；当前只有水平手枪弹，二维 / 霰弹 / 火箭由 T01 / T02 接入 |
| `ExplosionResolver` | `resolve(state, ExplosionRequest) -> ExplosionHit[]`；请求含 owner / source / center / radius / 中心与边缘推力 | 只有签名，没有运行时实现；T02 负责共享计算与遮挡 |
| `MapDefinition` | ID / 名称、尺寸、平台、出生点、边界、可选主题 / 英文副标题 / 描述 / 强调色 | 无投放点、完整导航图 |
| `BattleEvent` | shot / hit / ringout / respawn / phase / overtime / finished | 无投弹、爆炸、拾取、武器切换事件 |
| `SaveData` | version 1、设置、最近模式 / 地图、P1/P2 外观、累计统计、最后结果 ID | 无跨版本迁移、键位、战役、教学或清档；历史结果去重仍待 T12 |
| `CharacterAppearance` | style、hat、outfit、color、skin；复制到 `ActorConfig.appearance` | 只决定造型，不改变碰撞、击退或移动 |
| `createMatchConfig` 第三参数 | 可选 `mapId` / `appearances` / `matchId`；应用传存档选择和每局 ID，旧调用保留训练台默认 | 对局创建后不接受 UI 修改存档来改变当前局 |

T00 的首批契约不是玩法完成声明：`ActorState.weapon` 目前始终由 `BASIC_PISTOL` 创建，`bombPressed` 始终为 false，`ExplosionResolver` 只有类型签名。T01 / T02 / T06 接入时必须补真实行为、默认键位和清理路径；不要把这些字段当作已可用的入口。

`BattleSimulation.step(dt, inputs)` 是底层更新入口；`MatchRunner.advance(milliseconds, readHuman)` 加上固定步长和 AI。测试可以通过模拟器设置场景；产品代码不能照搬测试方式任意写状态。

## 8. 启动和本机说明

通用环境：Node.js 22.12+，建议 24 LTS；使用 `package.json` 指定的 pnpm 和现有锁文件。

```powershell
cd D:\Code\gun-brawl
pnpm install
pnpm dev
# 另一个终端
pnpm test
pnpm build
pnpm test:browser
pnpm test:visual
```

开发服务器默认 `http://127.0.0.1:5173/`。先检查已有服务，不要重复占端口；跨会话不能假定此前的终端进程仍在。

当前机器此前使用 Node 24.19.0。如果 `pnpm` 未在 PATH，可使用已验证的后备入口：

```powershell
& 'C:\Users\26914\.cache\codex-runtimes\codex-primary-runtime\dependencies\bin\fallback\pnpm.cmd' test
```

同一路径后接 `dev`、`build` 或 `test:browser`。这是本机工具路径，不要写入运行时代码，也不要假定其他开发机存在。

浏览器检查优先选择已安装 Chrome / Edge；可设置 `GAME_TEST_URL`、`PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`。截图和临时调参文件在被忽略的 `artifacts/`；不能把它当作任务源文件或正式设计依据。
