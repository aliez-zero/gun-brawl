更新：2026-10-17（北京时间）。状态：已完成。负责人：当前会话。工作区：`D:\code\gun-brawl`（`main`）。基线：`332998d`（源码基线）/ `1cc7358`（文档同步）；T00 契约提交见本地 Git 历史。

## 实际交付

T00 只做公共契约、默认值、生命周期顺序与验证，不实现六枪、炸弹或投放玩法。当前三模式、默认键位、手枪击退和 31 项原始回归保持。

### 武器与弹丸

- `WeaponDefinition` 增加 `maxAmmo: number | null`；`null` 表示无限弹，基础手枪为 `null`。
- 新增 `WeaponInstance { definition, ammoRemaining }`、`createWeaponInstance(definition)`、`ActorState.weapon`。
- `MatchConfig.startingWeapon` 是出生 / 复活 / 加时复位目标；拾取只换当前实例，不修改配置。
- `ActorState.fireCooldown` 继续由角色持有，切枪不清零；T01 在此之上做有限弹、耗尽回退和六枪注册表。
- `Projectile` 增加 `weaponId`、`velocity: Vec2`、`impulse: Vec2`；发射时冻结，`distanceRemaining` 仍限制射程。换枪不改变在途弹丸；二维速度供霰弹 / 火箭接入。
- `CombatSystem` 不再直接引用 `BASIC_PISTOL`，改为读 `actor.weapon.definition`，命中应用弹丸快照的 `impulse`。
- HUD 生命状态行改为读 `actor.weapon.definition.name` 与 `ammoRemaining`；手枪仍显示“基础手枪 · ∞”。

### 投弹与爆炸

- `ActorInput.bombPressed` 为按下边沿；`idleInput`、`KeyboardInput`、`BotController` 默认 `false`，连续射击语义不变。
- 当前没有投弹键绑定、HUD 或可点击入口；T02 做真实炸弹后由 T06 接默认候选 K / 小键盘 1，未接入前不显示为可用。
- 新增 `ExplosionSource`、`ExplosionRequest { ownerId, source, center, radius, centerImpulse, edgeImpulse }`、`ExplosionHit { actorId, impulse }`、`ExplosionResolver.resolve(state, request)`。
- `ExplosionResolver` 目前只有类型签名，没有运行时实现或空系统；T02 实现共享计算、遮挡、引信和炸弹系统，T01 火箭消费。

### 生命周期与结果 ID

- 初始化：`BattleSimulation` 用 `MatchConfig.startingWeapon` 为每个角色创建 `WeaponInstance`。
- 复活：`respawnActor` 从 `state.config.startingWeapon` 恢复武器和满弹 / 无限弹，并清空冷却；`LifeSystem` 只负责计时触发。
- 加时：`MatchSystem` 清空弹丸后对并列领先者调用 `respawnActor`；T02 / T03 接入时还必须清炸弹、箱子、预告和引信。
- 重赛 / 训练重置：`GameApplication.start` 创建新配置和新 `MatchRunner`，`ArenaScene.startMatch` 替换旧 runner；不继承旧局弹丸、计时或武器实例。
- 结果 ID：`GameApplication` 每局生成 `matchId`，`createMatchConfig` 放入 `MatchConfig`，`MatchSystem` 优先写 `MatchResult.id`；缺省保留 `seed-mode` 兼容旧调用。`SaveStore` 仍只保存 `lastResultId`，历史去重归 T12。

### 设置 / 存档 / 视图边界

- `SaveStore` 仍由 T12 负责人独占；应用层调用 `persist` / `recordResult`，视图只发回调。
- 设置页暂时仍在 `GameUI`；T06 交付独立设置组件时提供挂载 / 卸载 / 保存回调，集成者接线。
- 外观 / 地图编辑器已有“独立组件渲染 + 应用回调保存”的先例；新页面沿用，不直接写 localStorage。
- 当前只有 `D:\code\gun-brawl` 一个工作区；后续并行任务使用分支 / worktree，不改公共文件的所有权约定。
