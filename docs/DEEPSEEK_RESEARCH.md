# 大模型实时游戏 Agent 调研与落地方案

更新：2026-10-19。本文记录公开资料中对本项目最有用的结论，以及已经落到代码里的部分。当前项目使用结构化游戏状态，不依赖视觉模型；视觉输入适合跨游戏泛化，但会增加识别误差和延迟。

## 公开方案的共同结论

| 资料 | 关键做法 | 对本项目的启发 |
| --- | --- | --- |
| [ReAct](https://arxiv.org/abs/2210.03629) | 推理与行动交替，并把环境反馈带回下一轮计划 | 每次动作之后传回位移、落台、状态和是否卡住，避免模型重复同一错误 |
| [Reflexion](https://arxiv.org/abs/2303.11366) | 不更新模型权重，保存语言化的失败经验，在后续任务使用 | 当前先保存有界动作结果；后续可在每局结束后生成短 playbook，不把完整对局塞进上下文 |
| [Voyager](https://arxiv.org/abs/2305.16291) | 自动课程、可复用技能库、执行错误反馈和自验证 | 把平台导航、回台、抢箱、避炸弹作为本地技能，由模型选择意图而不是逐帧重算物理 |
| [SIMA](https://deepmind.google/discover/blog/sima-generalist-ai-agent-for-3d-virtual-environments/) | 用稳定的键鼠动作接口控制角色，模型输出动作并通过短任务训练 | 游戏模拟仍保持 60Hz，模型只输出短动作片段；不让网络请求进入核心模拟 |
| [AgentBench](https://arxiv.org/abs/2308.03688) | 多环境评测显示长程推理、决策和指令遵循是主要失败点 | 评测要记录有效指令率、卡住率、回台率、击出率和延迟，不能只看胜负 |
| [RealtimeBench / TORSI](https://arxiv.org/abs/2610.20665) | 实时环境中慢速教师和快速学生分工；在暂停状态复盘并把改进写成可复用指令 | 对局中走快速本地执行路径；局间才做反思和策略更新，避免把模型等待时间暴露给角色 |

## 当前采用的架构

```text
DeepSeek（约 500ms 一次，选择 intent + 短动作）
        ↓ 状态、路线、威胁、上一动作结果
本地技能层（60Hz）
  - 平台路线 / 跳台 / 穿台
  - 卡住重规划
  - 对齐射击 / 换弹 / 抢箱
  - 弹丸、炸弹和边缘规避
        ↓ ActorInput
固定步长 BattleSimulation（唯一修改位置、生命和击退的地方）
        ↓ outcome
下一轮观测与动作记忆
```

这一层次解决了实时游戏中最常见的失败：模型延迟时角色停住、模型直接控制低级按键导致跳跃过期、模型不知道上一条动作有没有生效，以及模型把路线规划和瞄准物理混在一次语言输出里。

当前动作接口增加了可选的 `intent`：

- `recover`：优先回到 `safePlatform`，避开边缘和威胁。
- `attack`：靠近、转向并进行短 burst 射击。
- `collect`：只有路线安全时接近武器箱。
- `reposition`：调整高度或平台位置，保留落脚点。

模型仍可以提供 `moveX`、跳跃、穿台、开火、投弹和换弹；本地技能层只在模型声明需要路线能力、角色卡住或进入危险状态时补全，正常动作不会被完整规则 AI 替换。

## 已落地的代码改进

- [Protocol.ts](../src/game/ai/external/Protocol.ts)：观测包含路线、最近威胁、战术优先级、平台边缘和动作结果；所有字段在网关再次白名单校验。
- [ExternalInputController.ts](../src/game/ai/external/ExternalInputController.ts)：使用现有 `BotController` 的平台导航作为技能层，增加卡住重规划、自动瞄准、换弹、威胁规避和紧急回台。
- [DeepSeekClient.ts](../src/adapters/ai/DeepSeekClient.ts)：记录最近 8 条动作，并把上一条动作的位移、落台、状态反馈给下一轮。
- [deepseek.mjs](../server/ai/deepseek.mjs)：提示词改为分层优先级，支持 `intent` 严格枚举，仍限制 JSON 输出和 512K 单次上下文。

## 后续应该按这个顺序继续

1. **局间 playbook**：每局结束只提取 3—5 条失败经验，例如“右侧平台边缘连续失足”“跳跃后未保留落台”，保存上限并在下一局以规则摘要注入。反思请求应在局外执行，默认不阻塞对局。
2. **评测闭环**：固定种子跑 50—100 局，分别统计原规则 AI、纯 DeepSeek、混合执行三组；记录决策延迟、过期率、卡住率、回台成功率、命中率、击出率和平均存活时间。
3. **技能自验证**：让每个技能在模拟器中先用短 rollout 验证“是否仍有落脚点”，失败就拒绝动作并回退到安全技能。
4. **离线推理模型**：若要使用更慢的 reasoner，只在局间生成 playbook 或策略，不让它进入 60Hz 控制链路；实时层继续使用低延迟模型。
5. **视觉输入作为独立适配器**：只有要支持外部游戏或无状态接口时再接视觉模型；本项目的结构化遥测更快、更准确，也更容易做安全校验。

## 参考边界

这些论文证明的是架构方向和评测方法，不代表 DeepSeek 在本项目中的胜率。真实效果必须用相同地图、种子、武器和延迟分别跑对照实验；浏览器 mock 测试只验证链路，不产生模型能力结论。
