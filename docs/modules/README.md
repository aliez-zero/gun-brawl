## 如何分发

1. T00 已完成现有源码基线、首批公共契约和本地 Git 历史。后续并行任务可基于该基线创建分支 / worktree；不要在缺少当前源码的旧目录另建副本。
2. 从总看板核对依赖和文件归属，为一个 AI 分配一个明确模块；在总看板登记负责人、工作区、基线和状态。
3. 将对应模块文件末尾的开发指令发给该 AI，要求先读项目协作规则与当前状态。
4. 每个开发者交付独占范围的代码、测试与接入清单；公共文件由负责人整合。模块进入主流程并验收后再标完成。

本目录不维护另一份任务状态，认领和交付状态统一写在 [PARALLEL_PLAN.md](../PARALLEL_PLAN.md) 的总看板。子任务编号采用 Txx.1—Txx.5，可用于提交、交接和问题定位。

## 并行开发建议

| 批次 | 可以安排的模块 | 需要先对齐 |
| --- | --- | --- |
| 准备 | T00；T04 地图设计、T05 导航调研、T11 验收清单 | 源码基线、已有改动与接口范围 |
| 第一批 | T01 枪械、T02 爆炸、T04 地图、T06 改键、T12 存档；T05 纯导航 | T00 契约、公共文件唯一写入者 |
| 第二批 | T03 投放、T05 完整决策、T07 自定义、T01 火箭收尾 | 枪械 / 爆炸 / 地图数据真实接入 |
| 第三批 | T08 教学图鉴、T09 战役、T10 外观，T12 存档整合 | 完整玩法、独立组件与保存契约 |
| 每批及末期 | T11 回归；集成者统一接线和验收 | 测试证据、重置路径、当前功能状态 |

多人并行不意味着多人同时修改 types.ts、GameUI.ts 或 ArenaRenderer.ts。共享接口与接线的顺序以总计划为准。
