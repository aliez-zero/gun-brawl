已接入子集：本轮在 v1 原 key 下增加 `selectedMapId`、两位玩家 `appearances` 和两名玩家的 `bindings`；逐字段校验 / 旧档补默认 / 混搭保存 / 损坏回退已有测试。音量、震动、模式、统计和结果标识保持兼容。后续开发保留这些字段，不能把改 key 或清空旧档作为迁移。完整记录见 [地图 / 外观交付](../updates/2026-10-17-appearance-maps.md) 与 [改键交付](../updates/2026-10-18-keybindings.md)。

T00 已提供结果 ID 接入点：`GameApplication` 每局生成 `matchId` 放进 `MatchConfig`，`MatchSystem` 优先用它写 `MatchResult.id`，旧调用缺省仍回退 `seed-mode`。当前 `SaveStore` 仍只保存 `lastResultId`；历史 / 交错重复的去重范围、教学 / 战役字段和迁移仍由 T12 完成，不能把“每局 ID 唯一”说成“历史去重已完成”。键位字段已由 T06 接入。

## 模块范围与验收

- **目标 / 需求**：F14，并服务设置 / 自定义 / 战役 / 外观；A26、A29。
- **拥有路径**：`src/storage/SaveStore.ts`、建议的迁移 / 校验模块、`tests/save-migration.test.ts`；清档 UI 与 MatchSystem 结果 ID 由集成者接入。
- **具体工作**：v1 有效数据迁移；键位 / 最近配置 / 教学 / 外观 / 战役字段；校验范围与引用；未知 / 损坏数据降级；清档确认和重新初始化；对局 ID 与种子解耦。
- **集成契约**：迁移时既检查新格式也读取旧命名空间 `gun-brawl:save:v1`；不得只换 key 导致旧设置丢失。统一提供设置 / 进度的写入方式，各 UI 不自行 localStorage。
- **验收**：音量 / 震动 / 基本战绩从 v1 保留；损坏字段局部回退；读写失败继续游玩且提示一次；同局重复通知不多计，相同种子新局正常计；训练和未完成退出不计正式场次；战役独立提交。
- **依赖与边界**：先冻结字段，再允许其他任务消费；对交错重复结果是否需要有限历史去重给出明确方案，不能把仅保存 lastResultId 描述为任意历史去重。
